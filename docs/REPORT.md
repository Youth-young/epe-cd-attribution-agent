# EPE-CD 원인 귀속 에이전트 — 프로젝트 보고서

작성: 2026-09 · 데모 https://epe-cd-attribution-agent.vercel.app

---

## 0. 요약

**주제** — ACI CD 이탈의 원인이 노광인지, 식각인지, 아니면 계측 자체인지를
좌표계 성분 분해로 귀속하는 에이전트.

**핵심 주장** — 반도체 공정 이상 분석에서 흔히 놓치는 세 번째 선택지가 있다.
"공정이 아니라 자(尺)가 틀렸을 가능성"이다. 이 에이전트는 그것을 명시적 판정 대상으로
올리고, 근거가 부족하면 원인을 지목하지 않고 보류한다.

**결과** — 정상 204 로트 오경보 0, 주입 이상 5종 중 4종 전량 검출,
**계측 drift를 식각 원인으로 오귀속한 사례 0건**.

**성격** — 합성 데이터 기반 개념 검증(PoC)이다. 실제 fab 데이터로 검증되지 않았다.

## 1. 배경과 문제 정의

### 1.1 EPE와 CD 성분

미세화가 진행될수록 EPE(Edge Placement Error) 예산이 줄어 "조금 틀린 것"이 곧 fail이 된다.

```
EPE = Overlay error + CD variation
```

이 프로젝트는 **CD variation 성분에 한정**했다. 오버레이는 입력 컨텍스트로만 받고,
"이번 이탈이 CD 성분이 주범인지"를 가르는 데만 쓴다. 범위를 좁힌 이유는 §7.2에 있다.

### 1.2 왜 원인 귀속이 병목인가

ADI(현상 후)와 ACI(식각 후)는 비대칭이다.

| | ADI | ACI |
|---|---|---|
| 측정 대상 | 레지스트 패턴 | 실제 소자 구조 |
| 되돌리기 | **가능** (rework) | 불가능 |
| 최종 결과와의 거리 | 멀다 | 가깝다 |
| 포착 범위 | 노광 오차 | 노광 + 식각 오차 |

즉 **판정이 늦어지는 만큼 손실이 확정된다.** 그런데 ACI CD가 흔들렸을 때
"노광 탓이냐 식각 탓이냐"는 서로 다른 조직이 서로 다른 데이터를 들고 논의하는 사안이고,
그 시간 동안 rework window가 닫힌다.

### 1.3 계기

계측 정합성 실습(3-way CD split)에서 ADI/ACI/단면 CD를 회귀로 이어 Target을 잡았다.
그때 알게 된 것은 **같은 웨이퍼의 CD가 측정 단계마다 다르고, 그 관계를 세워야 비로소
제어 가능한 하나의 숫자가 된다**는 사실이었다.

여기서 질문이 생겼다. 그렇다면 그 관계 자체가 흔들렸을 때는 어떻게 아는가?
공정이 변한 것과 자가 변한 것을 무엇으로 구분하는가?

이전에 참여한 결함 분석 에이전트에서는 구현을 팀원이 주도했고 본인은 결과를
교차 검증하는 역할이었다. 도메인은 알지만 판정 구조를 몰라 "맞다/틀리다"만 말할 수
있었다. 이번에는 문제 정의부터 판정 로직, 검증 기준까지 직접 설계했다.

## 2. 현업 계측 구조 — 무엇을 본떴는가

데이터 설계가 현실성을 잃는 지점은 대부분 "측정이 얼마나 성기게 이뤄지는가"를 모를 때다.
그래서 먼저 현업 구조를 정리하고, 그 구조를 데이터에 반영했다.

### 2.1 CD는 무엇으로 재는가 — 계층 구조

| | OCD (scatterometry) | CD-SEM | 단면 SEM / TEM |
|---|---|---|---|
| 성격 | 비파괴 · 고속 · 고밀도 | 비파괴 · top-down 실상 | 파괴적 |
| 강점 | CD + height + SWA + profile 동시 취득, in-line 피드백용 | 임의 형상 · 국소 결함, 직관적 | 절대 기준 |
| 약점 | model-based → 라이브러리를 실측으로 보정해야 함, 주기 격자 필요 | point 측정이라 throughput 낮음, 레지스트 e-beam damage/shrink | 샘플링 극소, 웨이퍼 소모 |

현업에서는 하나만 쓰지 않는다. **in-line 모니터링과 R2R 피드백은 OCD 위주**,
CD-SEM은 OCD 모델 보정과 이상 시 국소 확인, 단면은 최종 기준으로 주기 보정에 쓴다.
실습의 ADI CD / ACI CD / VSEM CD 3축이 정확히 이 계층이고,
그래서 그 실습의 주제가 "정합성 확보"였다.

### 2.2 오버레이는 어떻게 확인하는가

대부분 **스크라이브 라인의 전용 target**을 쓴다. 과거에는 image-based(box-in-box),
선단 공정은 diffraction-based(두 층 격자의 ±1차 회절 세기 비대칭). 문제는 target이
실제 device와 크기·밀도·스택이 달라 **device-to-target bias**가 생긴다는 점이고,
그래서 in-device 측정과 e-beam(after-etch) 실측이 이를 보정·검증한다.

되먹임은 ADI에서 측정 → APC/R2R로 다음 로트 스캐너 보정 → 스펙 아웃이면 rework.

### 2.3 샘플링의 현실

취준생 포트폴리오가 티 나는 1순위 이유가 "웨이퍼 전면 CD 맵"이다. 그런 건 없다.

| 항목 | 현업 실제 | 본 데이터 |
|---|---|---|
| 로트 | 25장 | slot 1~25 |
| ADI 측정 | 로트당 1~3장, 웨이퍼당 9~13 field × 3~5 site | 3장(slot 3/13/23) × 9 field × 5 site = **41점** |
| ACI 측정 | ADI보다 훨씬 성김, 전 로트가 아님 | **로트의 절반만**, 그중 1장 |
| 측정 위치 | ADI/ACI 같은 recipe·같은 site | 동일 sampling plan 공유 |
| 단면 기준 | 파괴적, 극소 샘플링 | 주 3회 5 site |
| 계측 tool 감시 | golden wafer 재측정 | 주 2회 9 site |

**ACI가 성기다는 사실이 그 자체로 설계 제약이다.** 절반의 로트에서는 ΔCD를 아예
계산할 수 없고, 에이전트는 그 경우 판정하지 않는다.

### 2.4 계측 장비 drift는 어떻게 잡는가

매주 단면을 뜨는 것이 아니라 **golden wafer(monitor wafer)를 반복 측정**해
offset과 precision을 추적한다. 공정이 건드리지 않은 웨이퍼가 움직였다면
답은 하나뿐이라는 논리다. 본 프로젝트의 핵심 판정 근거가 정확히 이것이다.

## 3. 데이터 — 어떤 형태이고, 어떻게 넣는가

### 3.1 앵커: 실습에서 그대로 가져온 값

BCD 조건에서 ADI 140/148/125 → ACI 120/128/105 → VSEM 100/108/85 이며,
세 단계의 차이가 각각 정확히 20 nm로 유지된다(기울기 1.0). 목표 BCD 90 nm를 대입해 얻은
값이 이 데이터셋의 중심이다.

| 항목 | 값 | 등급 |
|---|---|---|
| ADI CD Target | 130 nm | measured |
| ACI CD Target | 110 nm | measured |
| 단면 BCD Target | 90 nm | measured |
| etch bias (ACI − ADI) | −20 nm | measured |
| ADI→VSEM / ACI→VSEM 회귀 | 기울기 1.0, 절편 −40 / −20 nm | measured |
| 웨이퍼 내 CDU 3σ | 4.18 nm (생성 결과) | literature 범위 |
| dose sensitivity | −2.0 nm / 1% | literature |
| CD-SEM precision 3σ | 0.9 nm | literature |
| 슬릿 지문 · 챔버 반경 계수 · PM drift 기울기 | — | **assumed** |
| 프로파일 taper (BCD−TCD) 10 nm | — | **assumed** |

모든 상수에 measured / literature / assumed 등급을 붙였다.
**taper는 실습 데이터에 없다.** 식각 원인과 계측 원인을 가르는 보조 증거로 쓰려고
추가한 가정이며, 크기만 물리적으로 타당하게 잡았다. 전체 표는 `docs/00_data_basis.md`.

### 3.2 생성 모델 — 난수가 아니라 성분의 합

```
ADI CD = 목표
       + a_dose · ΔDose%              ← 웨이퍼 스칼라
       + b_focus · (F − F_best)²      ← field, Bossung 2차
       + Δ_slit(x_field)              ← field 내 X (스캐너 슬릿)
       + Δ_reticle(site_id)           ← site 고정, 모든 field에서 반복
       + Δ_track(r_wafer)             ← 웨이퍼 반경 (PEB plate)
       + ε_stoch + ε_meas(tool)

ΔCD   = etch bias
       + c_load · (패턴밀도 − 기준)   ← site 고정
       + Δ_chamber(r_wafer ; chamber) ← 웨이퍼 반경
       + d_pm · RF_hours              ← 시간 단조
       + ε
```

**좌표계 분리가 전부다.** 각 성분이 서로 다른 좌표계에 살기 때문에 분해가 가능하고,
그래야 원인 귀속이 성립한다. 이것이 물리적으로 정당한 이유는, 실제 fab에서
원인 분석을 하는 방식이 정확히 이것이기 때문이다.

### 3.3 데이터 형태 — 스키마

전부 **평면 CSV의 관계형 구조**다. 특별한 포맷이 아니다.

| 파일 | 단위 | 주요 컬럼 |
|---|---|---|
| `runs.csv` | 로트 × 웨이퍼 | `lot_id, date, day_index, scanner_id, reticle_id, dose_setpoint_pct, focus_offset_nm, etch_chamber, rf_hours_since_pm, adi_meas_tool, aci_meas_tool, aci_measured` |
| `meas_adi.csv` | 측정점 | `lot_id, wafer_slot, step, meas_tool, site_id, field_x, field_y, site_in_field, wafer_x_mm, wafer_y_mm, r_norm, pattern_density, cd_nm` |
| `meas_aci.csv` | 측정점 | 위와 동일 스키마 |
| `ref_xsem.csv` | 단면 표본 | `lot_id, wafer_slot, site_id, bcd_nm, mcd_nm, tcd_nm, taper_nm` |
| `tool_monitor.csv` | golden wafer | `date, day_index, meas_tool, site_id, cd_nm` |
| `sampling_plan.csv` | 좌표 정의 | `site_id, field_x, field_y, site_in_field, u_x, u_y, wafer_x_mm, wafer_y_mm, r_norm, pattern_density` |

규모 — 320 로트 / 40 생산일 / ADI 39,360행 / ACI 6,560행 / 단면 160행 / 감시 288행.

**설계상 반드시 필요한 두 가지 컬럼 구분**

1. `field_x/field_y`(field 인덱스)와 `site_in_field`(field 내 위치)를 **분리**해야 한다.
   합쳐지는 순간 intra-field 성분 분해가 불가능해진다.
2. `adi_meas_tool`과 `aci_meas_tool`을 **각각** 기록해야 한다.
   이 컬럼이 없으면 계측 원인 판정 자체가 성립하지 않는다.

### 3.4 현업도 이 형태를 쓰는가

**형태는 같고, 출처와 규모가 다르다.**

같은 점 — 계측 결과는 실제로 측정점 단위의 평면 테이블로 나온다. lot/wafer/site 키,
웨이퍼 좌표와 field 좌표, 측정 장비 ID, 타임스탬프, 측정값, 품질 플래그.
설비 컨텍스트(스캐너·챔버·recipe·PM 이력)는 별도 테이블에 있고 lot 키로 조인한다.
이 프로젝트의 스키마는 그 구조를 그대로 본떴다.

다른 점 —

- 현업은 MES/YMS 같은 시스템에서 나오고, 컬럼명과 단위가 fab마다 다르다
- 품질 플래그, 재측정 이력, recipe 버전, 정정 이력 등 컬럼이 훨씬 많다
- OCD를 쓰면 CD 외에 height·SWA·profile 파라미터가 함께 붙는다
- 규모가 수십~수백 배 크고, 결측·중복·이상치가 훨씬 지저분하다

즉 **본 데이터는 현업 테이블의 최소 골격**이다. 판정 로직에 실제로 필요한 컬럼만 남겼다.

### 3.5 데이터를 어떻게 넣는가

세 가지 경로가 있다.

**(a) 파라미터만 바꿔 재생성** — `config/config.yaml`의 상수(목표 CD, etch bias, 지문
진폭, 주입 시나리오)를 수정하고 `python run.py`. 데이터·분해·판정·웹이 한 번에 갱신된다.

**(b) 실측 CSV로 교체** — `data/`의 6개 파일을 위 §3.3 스키마에 맞춰 바꾸고
`python engine/analyze.py`만 실행한다. 생성기는 건너뛴다. 컬럼명이 다르면
매핑 스크립트를 한 장 두는 것이 실제 작업이 된다.

**(c) 관리 한계는 자동 산출** — 임의로 설정하지 않는다. 엔진이 **기준선 구간(생산일 0–9)의
평균과 3σ**로 스스로 계산한다. 데이터를 바꾸면 한계도 따라 바뀐다.

교체 시 반드시 확인해야 할 것 — `validation/sanity` 항목(웨이퍼 내 CDU 3σ,
ADI–ACI 회귀 slope, etch bias 평균과 산포, golden wafer 재측정 산포)이
물리적으로 납득 가능한 범위에 있는지.

## 4. 에이전트 설계

### 4.1 계층 분리

```
[도구 계층]  결정론적 Python — 숫자를 만드는 유일한 곳
     ↓
[추론 계층]  LLM — 숫자를 해석하고 다음에 무엇을 확인할지 결정
     ↓
[게이트]     코드 — LLM 결론이 규칙의 require 조건을 만족하는지 재검증
     ↓
[출력]       판정 / 판정 보류
```

**LLM은 단 하나의 숫자도 생성하지 않는다.** SKILL.md에 절대 규칙으로 명시했고,
도구가 돌려주지 않은 수치는 답변에 쓰지 못한다.

### 4.2 도구 표면

```bash
python engine/tools.py list --abnormal          # 이상 판정 로트 목록
python engine/tools.py lot <LOT>                # 로트 컨텍스트 + 지표
python engine/tools.py decompose <LOT>          # 좌표계별 성분 분해와 관리 한계
python engine/tools.py metrology --tool <T> --day <D>   # golden wafer drift 추이
python engine/tools.py chambers --day <D>       # 챔버별 ΔCD 비교
python engine/tools.py rules --signature <SIG>  # 걸린 signature에 해당하는 규칙만
python engine/tools.py verify <LOT>             # 게이트 통과 여부
```

`rules --signature`가 **점진적 공개의 실물**이다. 규칙 6종 전체를 매번 컨텍스트에
밀어 넣지 않고, 한계를 벗어난 지표에 해당하는 규칙만 가져온다.

### 4.3 분해 방법

ADI 잔차를 **하나의 설계행렬로 동시 회귀**한다.

```
[ 상수 | (r/R)² | field 내 site 더미 ]
```

성분을 순차적으로 빼면 서로를 오염시킨다. 특히 슬릿 지문이 반경 좌표와 부분적으로
상관되므로, 함께 풀어야 반경 계수가 왜곡되지 않는다. site 더미는 슬릿과 레티클을
함께 담으므로, 그다음 단계에서 field 내 X에 대한 선형 성분(슬릿)과 나머지(레티클)로
한 번 더 나눈다.

### 4.4 판정 규칙과 게이트

| 규칙 | 조건 | 요구 증거 | 조치 |
|---|---|---|---|
| PHOTO_DOSE | 스칼라 성분 이탈 | 반경·레티클 정상 | dose 보정량 산출 → R2R |
| PHOTO_TRACK_RADIAL | 반경 성분 이탈 | ΔCD 정상 또는 부재 | PEB plate 온도 맵 점검 |
| RETICLE_CD_ERROR | site 고정 성분 이탈 | 모든 field에서 반복 | 레티클 교차 노광 확인 |
| ETCH_CHAMBER | ΔCD 이탈 | 챔버 편중 · 계측 정상 · **감시 데이터 신선** · taper 모순 없음 | 챔버 격리, PM 주기 재검토 |
| METROLOGY_TOOL_DRIFT | ΔCD 이탈 | golden wafer 이동 | **공정 조치 보류**, CD-SEM 재캘리브레이션 |
| INDETERMINATE | ΔCD 이탈 | — | 추가 측정 요청 |

**판정 순서** — 되돌릴 수 있는 시점을 먼저 본다. ADI 계열(레티클 → 트랙 → dose)을
먼저 검사하고, 그다음 ΔCD 계열을 본다. ΔCD 이상에서는 **golden wafer가 움직였는지를
가장 먼저** 확인한다. 자가 틀린 상태에서 공정을 조치하면 정상 설비를 건드리게 된다.

**기권 설계** — 근거가 부족하면 억지로 답하지 않고 보류한다.
`ETCH_CHAMBER`는 계측 감시 데이터가 2일보다 오래됐으면 "계측이 정상"이라고 단정하지
않는다. **오답보다 기권이 나은 도메인**이라는 판단 자체가 설계 결정이다.

### 4.5 스킬 구성 (harness engineering)

```
.claude/skills/epe-attribution/
├── SKILL.md                          절차 · 도구 목록 · 금지사항 (짧게)
└── reference/attribution_rules.yaml  규칙 6종 (필요할 때만 읽음)
```

에이전트를 만들었다는 말의 실체는 프롬프트가 아니라 **컨텍스트를 어떻게 통제했는가**다.
네 가지로 정리된다.

1. **점진적 공개** — SKILL.md에는 절차만, 상세 기준은 reference에 두고 필요할 때만
2. **도구로 사고를 강제** — "생각해보라"가 아니라 "확인하려면 이 도구를 불러라"
3. **Verification Gate** — LLM 결론을 코드가 재검증, 불일치면 기각
4. **기권 설계** — 근거 부족 시 보류 + 필요한 추가 측정 명시

외부 스킬은 gstack 23개 중 3개(`/review`, `/qa`, `/document-release`)만 설치했다.
스킬을 많이 깔면 세션마다 모든 설명이 컨텍스트에 올라가고, 한도를 넘으면 일부가 조용히
누락된다. gstack 자체도 이를 인지해 설치 트리의 토큰 비용을 감사하는 도구를 함께
제공한다. **넣을수록 좋아지는 구조가 아니다.**

## 5. 결과

### 5.1 자동 산출된 관리 한계

기준선 구간(생산일 0–9)에서 엔진이 스스로 계산한 값이다. 손으로 정하지 않았다.

| 지표 | 관리 한계 |
|---|---|
| ADI 스칼라 | ±1.47 nm |
| ADI 반경 | ±0.78 nm |
| 레티클 반복 | ±0.37 nm |
| ΔCD 편차 | ±0.99 nm |
| golden wafer drift | ±0.90 nm |
| 챔버 편중 | ±0.79 nm |

정상 공정에도 고유 지문(반경 프로파일 등)이 있으므로, 절대값이 아니라
**기준선 대비 편차**로 판정한다.

### 5.2 블라인드 평가

`validation/ground_truth.csv`를 판정 경로에서 읽지 않고, 판정 후에만 대조했다.

| 실제 | 판정 성공 | 미검출 | 보류 | 오귀속 |
|---|---|---|---|---|
| 정상 204 | 204 | — | 0 | **0** |
| 노광 dose 16 | 16 | 0 | 0 | 0 |
| 트랙 반경 32 | 32 | 0 | 0 | 0 |
| 레티클 18 | 16 | 2 (발생 초기) | 0 | 0 |
| 식각 챔버 13* | 13 | 0 | 0 | 0 |
| 계측 drift 11* | 8 | 0 | 3 | **0** |

\* ACI 측정 로트 기준. ACI가 없는 로트에서는 ΔCD를 계산할 수 없으므로 판정하지 않는다.

**대표 지표는 오귀속 0건이다.** 계측 drift를 공정 이상으로 오판해 정상 챔버를
조치하게 만든 사례가 없다.

### 5.3 대표 케이스 — S4와 S5는 왜 구분이 어려운가

두 시나리오는 원시 데이터만 보면 동일하게 보인다. ADI 정상, ΔCD가 서서히 커짐.

| | 식각 챔버 PM drift | 계측 tool offset drift |
|---|---|---|
| ADI | 정상 | 정상 |
| ΔCD | 이동 | 이동 |
| 챔버 분포 | **특정 챔버에 몰림** | 모든 챔버에서 균등 |
| 측정 장비 상관 | 없음 | **특정 CD-SEM에서만** |
| golden wafer | 정상 | **같은 방향으로 이동** |
| 단면 taper | 함께 변함 | 변하지 않음 |

실제 판정 사례(L0283, 계측 drift):

```
ΔCD 편차          +2.37 nm   (한계 ±0.99)  → 이탈
CDSEM-B golden    +1.10 nm   (한계 ±0.90)  → 이탈
CH-A 챔버 편중    +0.74 nm   (한계 ±0.79)  → 정상
챔버별 ΔCD        CH-A +1.39  CH-B +0.89  CH-C +0.15  CH-D +1.46
```

세 챔버가 동시에 흔들렸다. 챔버 문제라면 하나만 흔들려야 한다.
게이트가 식각 귀속을 막고 계측으로 판정한다.

### 5.4 배포 후 QA

`/qa`로 배포된 URL을 실제 브라우저에서 검증했다. Health score 97 → 100.

**High (수정·재검증 완료)** — 320개 로트 목록이 순수 마우스 클릭용 `<div>`라
키보드·스크린리더로 전혀 접근할 수 없었다. Tab이 필터 버튼에서 헤더로 바로 넘어갔다.

## 6. 의의 — 현업과 비교해서

### 6.1 같은 것

- **분해 축이 같다.** 신호가 어느 좌표계에 사는지로 원인을 가르는 것은
  실제 fab의 원인 분석 방식 그대로다.
- **감시 방식이 같다.** golden wafer 재측정으로 계측 장비 offset을 추적하는 것은
  현업 관행이다.
- **되먹임 구조가 같다.** ADI 시점 판정 → 다음 로트 보정 또는 rework.
- **데이터 스키마가 같다.** 측정점 단위 평면 테이블 + 설비 컨텍스트 조인.

### 6.2 다른 것 — 이 프로젝트의 주장

업계는 **측정 정확도를 높이는 방향**으로 간다. 더 조밀하게, 더 정확하게, 더 빠르게.

이 프로젝트는 그 전제인 **"측정을 신뢰할 수 있는가"를 명시적 판정 대상으로 올렸다.**
계측 drift는 어느 좌표계에도 살지 않아서 원시 데이터만으로는 공정 이상과 구분되지 않고,
잘못 판정하면 정상 설비의 recipe를 건드린다. 이것은 잘못된 조치 중에서도 가장 비싼 부류다.
정상이던 공정을 스스로 망가뜨리기 때문이다.

**그래서 판정 순서를 "자를 먼저 확인한다"로 고정했다.** golden wafer가 움직였다면
챔버 편중 여부와 무관하게 계측을 먼저 바로잡고 재판정한다.

### 6.3 업계 동향과의 대조

- 계측·연산 쪽은 고밀도 맵 추정과 in-device 측정으로 **"덜 재고 더 아는"** 방향
- 식각 장비 쪽은 챔버 자가 진단과 가상 계측(virtual metrology)
- 공통적으로 가상 계측과 R2R 제어의 결합으로 수렴 중

이 프로젝트의 방향은 그 흐름과 충돌하지 않는다. 오히려 가상 계측을 신뢰하려면
**실측 계측 자체의 신뢰도를 계속 감시해야** 하므로 보완 관계에 가깝다.

**예상되는 실제 장벽은 기술이 아니라 조직이다.** Photo, Etch, Metrology가 서로 다른
조직이고 데이터 스키마가 다르다. 그래서 장비사 관점에서는 자사 장비 데이터부터
시작하는 것이 현실적이라고 본다.

### 6.4 이 프로젝트가 의미 있는 지점

1. **판정 근거를 전부 노출한다.** 지표·값·한계·이탈 여부가 표로 나오고,
   게이트 통과 조건이 각각 ✓/✗로 표시된다. 블랙박스가 아니다.
2. **숫자와 추론을 분리했다.** LLM이 값을 지어낼 여지를 구조적으로 막았고,
   재현성 테스트로 확인했다.
3. **틀릴 수 있는 지점을 스스로 표시한다.** 감시 데이터가 오래되면 판정을 거부한다.
   이 거부 3건은 설계 실패가 아니라 설계 의도다.
4. **데이터의 근거를 등급으로 공개했다.** measured / literature / assumed.
   숫자 하나를 지적받아도 "그건 가정입니다"라고 답할 수 있다.

## 7. 한계

### 7.1 데이터

1. **합성 데이터다.** 실제 fab 데이터로 검증되지 않았다.
2. **성분을 선형 가산으로 가정했다.** 실제로는 dose–focus 상호작용,
   etch bias의 CD 의존성 같은 결합항이 있다.
3. **확률 성분을 단순 가우시안으로 근사했다.** 실제 stochastic 성분은 이보다 무겁다.
4. **주입 신호의 크기에 가장 확신이 없다.** 크게 넣으면 판정이 쉬워져 의미가 없고,
   작게 넣으면 검증이 불안정해진다. 현업 담당자의 검토를 받지 못했다.

### 7.2 범위

5. **EPE 중 CD 성분만 다뤘다.** 특히 프로파일 비대칭이 회절 기반 오버레이 측정에
   주는 bias — CD 성분과 오버레이 성분의 상호작용 — 은 범위 밖이다.
6. **단일 layer, 단일 패턴(positive tone L/S) 기준**이다.
   실제 EPE는 여러 layer 누적이다.
7. **단일 원인만 판정한다.** 실제 이상은 복합 원인이 흔하고,
   이 데이터로는 그 판정력을 검증할 수조차 없다.

### 7.3 판정

8. **원인 귀속까지이고 근본 원인은 아니다.** 식각으로 귀속돼도 챔버 컨디션인지
   부품 열화인지는 설비 센서 데이터가 필요하다.
9. **레티클 이상 2건을 발생 초기에 놓쳤다.** 신호가 아직 관리 한계 아래일 때다.
   검출 지연은 원리적으로 남는다.
10. **반경 모델이 2차항 하나다.** 링 형태나 국소 hot spot 같은 고차 패턴은 잡지 못한다.

## 8. 개선 방향

| 순위 | 내용 | 필요한 것 |
|---|---|---|
| 1 | 실측 로트로 잔차 구조 재추정 | 실제 계측 데이터 |
| 2 | 복합 원인 판정 — 성분 기여도를 확률로 배분 | 다중 원인 라벨 데이터 |
| 3 | 설비 센서 결합 (OES, RF, 압력 트레이스) | 챔버 로그 접근 |
| 4 | 반경 모델을 고차·비모수로 확장 | 더 조밀한 샘플링 |
| 5 | 오버레이 성분 확장 | in-device / DBO 데이터 |
| 6 | 검출 지연 단축 — 누적합(CUSUM) 등 순차 검정 도입 | — (현 데이터로 가능) |
| 7 | 결함 좌표 맵과 결합 — CD drift와 결함 발생 위치의 공간 상관 | inspection 데이터 |

6번은 현재 데이터로도 가능한 개선이다. 지금은 로트별 독립 판정이라
"아직 한계 아래지만 계속 같은 방향으로 흐르고 있다"는 정보를 쓰지 못한다.

## 9. 현업 적용 가능성

### 9.1 그대로는 안 되는 것

- 파라미터가 합성 기준이다. 실제 노드·layer·recipe에 맞춰 전면 재보정해야 한다.
- 관리 한계 산출이 단순 3σ다. 실제로는 SPC 룰(연속 이탈, 추세)과 병행해야 한다.
- 데이터 파이프라인이 없다. MES/YMS 연동, 컬럼 매핑, 결측·재측정 처리가 전부 빠져 있다.

### 9.2 옮길 수 있는 것

- **좌표계 분해 로직** — 물리 구조에 기반하므로 노드가 바뀌어도 원리가 유지된다.
- **판정 순서** — "되돌릴 수 있는 시점 먼저, 계측 확인 먼저"는 조직과 무관하게 성립한다.
- **게이트와 기권 구조** — 자동 판정 시스템이 현장에서 신뢰를 얻으려면
  "모를 때 모른다고 하는" 동작이 필수다.
- **데이터 스키마 요구사항** — field 좌표 분리, 측정 장비 ID 별도 기록.
  이 두 컬럼이 없으면 어떤 알고리즘을 써도 계측 원인 판정이 불가능하다.

### 9.3 현실적인 첫 단계

전면 도입이 아니라 **기존 판정과 병행 운영하는 그림자 모드**가 맞다고 본다.
엔지니어가 내린 판정과 에이전트의 판정을 몇 달간 나란히 기록하고,
불일치 케이스만 리뷰한다. 그 로그가 쌓여야 (a) 관리 한계 튜닝,
(b) 복합 원인 라벨, (c) 실제 오조치 방지 효과 측정이 가능해진다.
