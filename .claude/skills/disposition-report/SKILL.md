# 3단계 · 조치 판정

## Trigger
- `cause-attribution`이 원인 후보를 반환했을 때
- 로트를 어떻게 처리할지(disposition) 물어올 때
- 게이트 통과 여부를 확인할 때

## 책임 범위
**조치 가능한가, 무엇을 할 것인가까지.**
성분 분해와 원인 귀속은 앞 두 스킬의 결과를 그대로 쓴다. 다시 계산하지 않는다.

## 절대 규칙
**최종 판정은 이 스킬이 내리지 않는다.** 결정론적 검증 게이트가 내린다.
게이트가 불충족을 반환하면 원인을 지목하지 않는다. 문장으로 우회하지 않는다.

## 도구
```bash
python engine/tools.py verify <LOT>       # 게이트 통과 여부와 미충족 조건
python engine/tools.py investigate <LOT>  # 전체 조사 경로를 한 번에 실행
```

## 판단 기준

**게이트 통과**
조치 대상 모듈과 조치 순서를 제시한다. 조치는 실행 가능한 단위여야 한다.
"확인해 본다"가 아니라 "무엇을 조회하고 무엇을 비교한다"까지 쓴다.

**게이트 불충족**
- 원인을 지목하지 **않는다**
- `unmet` 조건을 그대로 밝힌다
- 그 조건을 충족시키려면 어떤 측정이 추가로 필요한지 쓴다
- 상태는 `NEEDS_MORE_EVIDENCE`로 남긴다

**사람의 몫과 AI의 몫**
Lot 처리 같은 최종 판단은 사람이 한다.
이 스킬은 그 판단에 필요한 근거를 빠짐없이 정리하는 역할까지다.

## DoD
- [ ] `verify`를 호출했고 그 결과를 그대로 반영했다
- [ ] 게이트 불충족 시 원인을 지목하지 않았다
- [ ] 불충족 조건과 필요한 추가 측정을 명시했다
- [ ] 조치가 실행 가능한 단위로 쓰여 있다
- [ ] 앞 단계의 수치를 다시 계산하지 않고 그대로 인용했다

미충족이면 리포트를 내지 않고 `cause-attribution`으로 되돌린다.

## 출력 형식
판정 / 조치 대상 모듈 / 근거 3줄 / 다음 확인 사항. 그 이상 길게 쓰지 않는다.
